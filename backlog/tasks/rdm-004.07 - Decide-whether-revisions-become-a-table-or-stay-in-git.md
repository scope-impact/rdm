## Question

The source model versions every item in a `REVISION` table with `ATTRIBUTE_VALUE` rows hanging off the revision, so the value rows *are* the history. rdm has no revision table: history is git, and approval is "committed with no uncommitted changes".

Note what already works: rdm design gate implements approval-by-commit and treats a document with uncommitted changes as unapproved — verified live, editing 11 design documents flipped the gate red until commit. That is functionally Doorstop `reviewed` fingerprint, which the source model itself calls "a cheap substitute for a full revision table if the audit requirements allow it".

Decide whether the audit requirements allow it. This is the gating question for revision-pinned traces and for snapshots, so it is resolved before either.
